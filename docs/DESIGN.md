# lifeplan — дизайн v1

Личный планировщик: задачи по сферам, календарь, инбокс через Telegram, разборы с Claude, аналитика.
Только для одного пользователя. Рабочее имя `lifeplan`, можно переименовать.

## Принципы

1. **Ввод дешевле задачи.** Ты пишешь как получится (текст или голос в TG), структуру наводит ИИ: сначала бот, потом Claude на вечернем разборе.
2. **Логику ограничиваем строго, оформление — нет.** У задачи жёсткое типизированное ядро (статус, даты, матрица, оценка, связи): по нему считаются аналитика, синхронизация и прогресс. Содержимое (`body`) — свободный набор блоков, который ИИ собирает под конкретную задачу. Ограничены только *типы* блоков, их состав и порядок свободны.
3. **Источник истины — своя база Postgres.** Google Calendar и Google Tasks — это зеркала и каналы ввода, а не хранилище.
4. **Изменения от ИИ идут через план.** Claude (и бот в спорных случаях) не меняет данные напрямую: он создаёт план изменений (change plan), ты подтверждаешь, план применяется.
5. **Сначала API.** Веб, бот, CLI для Claude и будущий продукт с данными Garmin — всё это клиенты одного API.

## Модель данных

### Справочники
```
spheres      id, slug, name, color, icon, style jsonb, sort, archived
             -- Работа, Карьера, Учёба, Продукты, Быт, Досуг, Здоровье, Финансы (меняется)
projects     id, parent_id → projects (группы любой глубины), sphere_id, name, color, archived
tags         id, name, kind ('context' | 'label'), color
             -- context: @звонок @комп @в_дороге ≤15мин — «что могу сделать сейчас»
```

### items — одна таблица для задач, целей, событий и заметок
```
id            uuid
kind          'task' | 'goal' | 'event' | 'note'
title         text
body          jsonb   -- блоки, см. ниже
props         jsonb   -- свободные свойства конкретного типа (не для логики ядра)

sphere_id, project_id, parent_id (подзадачи, любая глубина)
status        'inbox' | 'todo' | 'doing' | 'waiting' | 'done' | 'cancelled' | 'someday'
important     bool    -- матрица Эйзенхауэра
urgent        bool    -- квадрант вычисляется из двух флагов

planned_date  date          -- «когда делаю»
start_at, end_at timestamptz -- слот: встреча или блок времени (MSK)
deadline      timestamptz   -- «когда крайний срок», отдельно от planned_date
estimate_min  int
weight        numeric default 1   -- вес для прогресса родителя или цели
postpone_count int                -- только для разовых; повторяющиеся не считаются

recurrence_id, occurrence_date    -- экземпляр повторяющейся задачи
source        'tg' | 'web' | 'claude' | 'gcal' | 'gtasks'
gcal_calendar_id, gcal_event_id, gtask_id, sync_etag
created_at, updated_at, done_at
```

**Прогресс** = Σ weight завершённых детей / Σ weight всех детей. Для цели считается по связям `part_of`. Если детей нет, прогресс не показывается (никаких «6 из 13» от балды).

**Чек-лист и подзадача — разные вещи.** Чек-лист — это блок в `body`: лёгкий, без дат и учёта времени. Подзадача — полноценный item со своей оценкой, статусом и весом.

### Связи
```
relations    from_id, to_id, type
             type: 'blocks'     -- to нельзя начать, пока не сделан from
                   'related'    -- тематическая связь
                   'follows'    -- цепочка этапов
                   'part_of'    -- задача → цель
                   'prepares'   -- задача → событие (подготовка к созвону)
```
Связь родитель → ребёнок хранится в `items.parent_id`. Граф строится из обоих источников.

### body: формат блоков
```json
[
  {"type": "md",        "text": "Свободный markdown"},
  {"type": "checklist", "items": [{"text": "...", "done": false}]},
  {"type": "link",      "url": "...", "title": "..."},
  {"type": "file",      "drive_id": "...", "name": "...", "mime": "..."},
  {"type": "ref",       "item_id": "..."},
  {"type": "callout",   "tone": "info|warn|ok", "text": "..."},
  {"type": "code",      "lang": "go", "text": "..."},
  {"type": "table",     "columns": [...], "rows": [[...]]},
  {"type": "comment",   "at": "...", "author": "me|claude", "text": "..."}
]
```
Веб рендерит каждый тип своим компонентом, неизвестный тип показывается как markdown. Новый тип блока = новый рендерер, менять схему БД не нужно. Заметки (`kind='note'`) заменяют Obsidian: всё живёт в вебе и доступно с любого устройства без платной синхронизации.

### Время, история, дневник
```
time_entries  id, item_id, started_at, minutes, source ('garmin_manual'|'tg'|'web'|'timer'), note
              -- сюда позже сможет писать и продукт с данными Garmin
recurrences   id, template_item_id, rrule, until; экземпляры генерируются на 14 дней вперёд
item_events   id, item_id, at, actor ('me'|'claude'|'bot'|'sync'), field, old jsonb, new jsonb
              -- журнал изменений: на нём строятся переносы, время в статусах, «долгожители»
journal_days  date pk, body jsonb, mood int null, summary text
attachments   файлы лежат в Google Drive (папка lifeplan/), в базе только drive_id
```

### Инбокс, планы изменений, брифы
```
inbox_messages  id, tg_message_id, text, voice_file_id, transcript, parsed jsonb,
                status ('new'|'proposed'|'accepted'|'deferred'|'rejected'), item_id, created_at
change_plans    id, author ('claude'|'bot'), summary, ops jsonb, status ('proposed'|'applied'|'rejected'),
                created_at, applied_at
                -- ops: [{op:"create"|"update"|"move"|"done"|"relate"|"delete", ...}]
briefs          id, date, kind ('evening'|'morning'|'weekly'), body, sent_at
```

## Компоненты

Один Go-модуль, один бинарник `lifeplan` с подкомандами: для одного пользователя лишние микросервисы не нужны.

| Подкоманда | Что делает |
|---|---|
| `lifeplan serve` | HTTP API + (v2) статика веба + горутины: TG-бот, планировщик (брифы 21:00 и 07:00, генерация повторов, синхронизация с Google каждые 5 мин) |
| `lifeplan migrate` | миграции (goose, как в tryberry) |
| `plan` (CLI) | клиент API для Claude Code на вечернем разборе: `plan inbox`, `plan day [дата]`, `plan week`, `plan propose plan.json`, `plan apply <id>`, `plan stats` |

### TG-бот
- Текст или голос → Groq Whisper (≈$0.04 за час аудио) → Claude Haiku 4.5 разбирает в черновик item.
- Ответ — карточка с кнопками `✅ принять` / `✏️ поправить` / `📥 на вечер`.
- `уборка 40м`, `собес 1ч20` → запись времени (time_entry) к подходящей задаче. Если неясно к какой, бот спрашивает кнопками.
- Пишет только твоему chat_id, остальных игнорирует.
- Ожидаемые расходы: инбокс 10–20 сообщений в день ≈ $1–2 в месяц на Haiku + центы на Whisper.

### Синхронизация с Google
- **Calendar.** Один календарь `LifeTask`; цвет события задаётся по сфере (`colorId`, 11 цветов Google) — проще и дешевле по запросам, чем календарь на каждую сферу. Всё, у чего есть `start_at`, выгружается. Правки в Google (перенос, переименование, удаление) подтягиваются обратно сверкой окна (−7…+60 дней) по etag; без syncToken — надёжнее с повторяющимися событиями. Основной календарь зеркалится (−1…+14 дней, только чтение): из него считается загрузка дня.
- **Tasks.** Список `Срочно` — ручной ввод днём, импортируется во входящие и закрывается в Google.
- **Drive.** Scope `drive.file`: приложение видит только свои файлы.
- OAuth-клиент тот же, что в tryberry, но **отдельный refresh-токен** со scope calendar + tasks + drive.file.

### Веб (v2)
Можно установить на iPhone как приложение (PWA), вход через Telegram Login. Экраны: День (таймлайн + список), Неделя, Канбан, Сферы, Граф, Аналитика, Дневник, Заметки.
Офлайн (v4): IndexedDB-очередь черновиков, отправка при появлении сети.

### Развёртывание
- Разработка в WSL (`docker compose up` с локальным Postgres).
- Прод: тот же VPS, **отдельный compose-проект** со своим Postgres (с tryberry ничего общего). В nginx tryberry добавляется server-блок для поддомена → `127.0.0.1:<порт>`.
- Бэкап: ежедневный `pg_dump` → Google Drive.

## Этапы
- **v1** — БД, API, бот (инбокс, голос, время), CLI `plan`, синхронизация с Calendar/Tasks, брифы 21:00 / 07:00.
- **v2** — веб: День, Неделя, Канбан, редактирование.
- **v3** — аналитика, граф, недельный отчёт.
- **v4** — офлайн-очередь, дневник с ИИ, веса подзадач в UI.

## Сделано в v4

- **Офлайн.** Сервис-воркер: оболочка и последние ответы API (network-first, кеш как запас). Записи без сети уходят в
  IndexedDB-очередь с `Idempotency-Key` и отправляются при появлении сети, открытии и возврате на вкладку. Сервер
  выполняет запись с ключом ровно один раз (`idempotency_keys`; при 5xx ключ освобождается).
- **Дневник.** `journal_days`: настроение 1–5, текст, итог. В вебе — вкладка с автосохранением и списком сделанного за день.
  В боте — смайлики под вечерним брифом, ответ на бриф и `/d текст` дописывают дневник. Claude читает `plan journal` и
  записывает итог дня `plan journal-summary`.
- **Веса.** Прогресс по весам считается в SQL для каждой задачи (подзадачи + `part_of` у целей), виден в списках; веса
  подзадач правятся прямо в карточке родителя.

## Разбор без ИИ

`parse.Rules` разбирает заметку правилами: относительные и календарные даты, время и диапазоны, «через N часов»,
длительность («на полтора часа»), дедлайны («до пятницы»), повторы («каждую субботу», «по вт и чт», «по будням»),
учёт времени («уборка 40м», «1ч20») с поиском задачи по основам слов, сферу по ключевым словам, «срочно/важно».
Без ключа Claude бот работает на правилах; с ключом — Claude, а правила — запасной путь при его ошибке
(`parse.Fallback`). Тот же разбор — у быстрого ввода и кнопки «Оформить» во входящих (`POST /api/quick`).
